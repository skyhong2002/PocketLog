## Problems and fixes

- #99: fixed-content fixture lacked a launcher entry. Added MAIN/LAUNCHER,
  rebuilt/installed, and verified real capture.
- #100: tailnet prerequisite and sandbox namespace/settings navigation were
  missing from the development runbook. Documented trusted connectivity,
  full component and CLEAR_TOP return; verified these steps.
- #101: UI Automation suppresses other accessibility services during inspection.
  Added optional deferred synthetic window and explicit helper-release runbook.
  Use `--relaunch` so launch extras reach a fresh fixture activity. Verified
  callback, editable rejection and secure-window rejection without inspection
  during the capture interval. This is tooling interference, not an established
  PocketLog capture-service defect.
- #102: Android truncated category percentages while web rounded (76% vs 77%
  for the same activities). Changed Android to nearest-integer rounding. Full
  Android checks passed; updated physical APK acceptance is pending.
- #103: before first unlock after reboot, the driver could not launch SystemUI,
  then reported a missing sandbox activity on debug recovery. Stopped device
  operations under the tool's failure rule and requested physical first unlock.
  This does not establish APK loss or an application crash.
- The custom OS rejects `run-as` SELinux context. Used supported UI diagnostics
  and authenticated synthetic API evidence; no SELinux change or root bypass.

## Outstanding acceptance

Reboot first-unlock recovery, grants restoration, offline image queue, shared
pause/resume, prolonged background/lock/Doze, network-policy/429 handling, and
updated APK physical verification are not yet accepted. Functional smoke and
short interactive tests do not establish every shipped feature or close #94–#98.

The user confirmed that an unplugged measurement period will be arranged later.
The phone is USB-powered during this session: **no battery baseline is claimed**.
#95 needs a recording-disabled baseline and at least 24 hours for each enabled
capture layer, with matched workload and budgets defined before measurement.
Do not fake unplugging battery state or substitute emulator/short tests.

At this checkpoint both OS grants are revoked. Disposable test services and the
private HTTPS route remain available for recovery tests; the current test device
key expires after one day. Tailscale remains installed as authorized. Production
upgrade and its verification must be recorded separately after completion.
