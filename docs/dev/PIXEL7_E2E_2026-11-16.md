  or activities were substituted for physical evidence.

## Problems and fixes

- #99: fixed-content fixture lacked a launcher entry. Added MAIN/LAUNCHER,
  rebuilt/installed, and verified real capture.
- #100: tailnet prerequisite and sandbox namespace/settings navigation were
  missing from the development runbook. Documented trusted connectivity,
  full component and CLEAR_TOP return; verified these steps.
- #101: UI Automation suppresses other accessibility services during inspection.
  Added optional deferred synthetic window and explicit helper-release runbook.
  Use `--relaunch` so launch extras reach a fresh fixture activity. Verified
  callback, editable rejection and secure-window rejection without inspection
  during the capture interval. This is tooling interference, not an established
  PocketLog capture-service defect.
- #102: Android truncated category percentages while web rounded (76% vs 77%
  for the same activities). Changed Android to nearest-integer rounding. Full
  Android checks passed; updated sandbox APK physically verified at learning 65%,
  unsorted 23%, work 12%, matching nearest-integer API durations.
- #103: before first unlock after reboot, the driver could not launch SystemUI,
  then reported a missing sandbox activity on debug recovery. Stopped device
  operations under the tool's failure rule and requested physical first unlock.
  After user unlock, the same installed component opened successfully, with saved
  data and revoked permissions intact. This did not establish APK loss or an app crash.
- #105: Compose reported existing containers running after the production tag
  changed, but their image IDs still identified the old image. Explicit recreation
  installed the tested candidate; added image-ID verification and rollback steps
  to the setup runbook.
- #106: Wi-Fi returned after reboot but Tailscale required opening its app to
  reconnect. Documented VPN recovery; existing credentials then synced without
  re-pairing.
- #107: deliberate force-stop/relaunch retained the encrypted image queue but
  accessibility was later found disabled. Added explicit enabled/bound checks
  and distinguished force-stop from low-memory reclamation. The attempted lock
  test with an unbound service is invalid and is not accepted.
- #108: source review found that a denied UsageStats scan saved only a cursor,
  losing the denied state. Restoration could therefore query the interval since
  the last denied check. Encrypted checkpoints now retain the observed permission
  state, discard old open sessions on transitions, and migrate legacy state with
  a fresh boundary. App resume reconciles state on the existing executor without
  extra periodic sampling. Regression checks cover transitions, restart, unchanged
  grants, migration and corruption. Updated sandbox APK installation succeeded;
  physical verification is pending. Background upload retries and the locked
  screen prevent confirmation of the initial phone observation.
- The custom OS rejects `run-as` SELinux context. Used supported UI diagnostics
  and authenticated synthetic API evidence; no SELinux change or root bypass.

## Outstanding acceptance

Shared pause/resume, prolonged background/lock/Doze, network-policy/429 handling,
and reboot with capture grants enabled are not yet accepted. Usage permission
restoration has a source-confirmed transition fix (#108), still awaiting physical
retest. A revoke-and-restore sequence entirely while PocketLog is not executing
cannot be inferred from a later current AppOps grant; this fix only establishes
boundaries for observed permission changes. Do not claim that unobserved case
passed. Functional smoke and short interactive tests do not establish every shipped feature or close #94–#98.

The user confirmed that an unplugged measurement period will be arranged later.
The phone is USB-powered during this session: **no battery baseline is claimed**.
#95 needs a recording-disabled baseline and at least 24 hours for each enabled
capture layer, with matched workload and budgets defined before measurement.
Do not fake unplugging battery state or substitute emulator/short tests.

At this checkpoint usage access has been restored; accessibility is off and the
phone is locked after the attempted lifecycle test. No forced Doze or simulated
battery state is active. Disposable test services and the private HTTPS route remain available for recovery tests; the current test device
key expires after one day. Tailscale remains installed as authorized.
